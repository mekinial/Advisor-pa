Nightly WhatsApp check for the adviser in <PA>/Me.md (you are the follow-up agent). Work in <PA>; read CLAUDE.md, Me.md, Preferences.md and Voice.md first. Never send a message, never contact anyone, never type in WhatsApp except a client's name in the chat search box. Don't edit the scripts during a run.

Needs config.json whatsapp.enabled = true. Part 2 only runs if whatsapp.read_chats = true (the adviser accepted that opening a chat shows blue ticks to the client). Caps and the "gone quiet" days are in config.json whatsapp.caps / quiet_days.

## Part 1: the list scan (script, no clicks)
1. `cd <PA> && ./pa hq_status start follow-up "Nightly WhatsApp check"`
2. If Drafts/Follow-ups/whatsapp-scan-<today YYYY-MM-DD>.md already exists (the background check ran), use it. Otherwise run `./pa whatsapp_scan run --no-post` (1–2 minutes). It sorts everyone the adviser has messaged by who sent the last message, puts newly "your turn" people on today's To message list, takes "Your turn"/nudge lines off for people the adviser already answered, and writes that report. If it fails, try once more after a minute; if it still fails: `./pa hq_status needs follow-up "Nightly WhatsApp check couldn't run: <reason>"` and stop.

## Part 2: read client and prospect chats (only if whatsapp.read_chats is true)
1. Use WhatsApp Web in Chrome with the Claude in Chrome tools (load them in one ToolSearch). Open https://web.whatsapp.com in a tab, wait ~8 s. If it says "WhatsApp is open in another window", click "Use here". If Chrome isn't connected, it asks for a QR code, or the list doesn't load after one retry: skip Part 2, post Part 1 (step 6) and add "chats not opened: <reason>" to the done line.
2. Read the chat list as text: javascript `[...document.querySelectorAll('#pane-side [role="row"]')].map(r=>r.innerText.replace(/\s+/g,' ').slice(0,120))`. Scroll the list to load older rows.
3. Pick the chats (1:1 client/prospect chats only):
   a. **Recent** (max caps.recent): every client/prospect chat with any new message since the last run (~24 h), from either side. Newest first.
   b. **Gone quiet** (max caps.quiet): clients whose last message, either side, is quiet_days+ old (dates from tonight's report, or a note's "on YYYY-MM-DD"). Skip anyone with a `./pa wa_notes show` note from the last 30 days, so each person comes up at most once a month. Oldest first. Their draft is a light, friendly check-in in the adviser's voice (how have you been, anything changed, happy to do a quick review), not "following up on my intro". Find them with the chat search box: click "Search or start a new chat", type the name as saved (first two words), wait 2 s, click the matching row under "Chats" (check the full name), read, then Escape to clear the search. If no chat is found, skip and note "no chat found".
   c. **Untracked clients** (max caps.untracked): `./pa wa_notes untracked --n <caps.untracked>`. Search each name as in b. No chat → `./pa wa_notes nochat "<name>"` (skipped for 90 days) and list them under "No WhatsApp chat" so the adviser can check the number. Chat found → read as in step 4, then `./pa wa_notes seen "<name>" <last chat date>` (updates the pipeline's Last Contact if newer). Check-ins from b + c together: max caps.quiet a night; past that, only save the note.
   d. **First-message check**: `./pa wa_notes intros` lists open first messages (TOP intros). For each one not checked before, search the name in the chat search box without opening the chat. A 1:1 chat listed under "Chats" (also under a nickname) → `./pa wa_notes existing "<full name as listed>" <last chat date> "existing chat as '<chat name>'"` (closes the first message; tomorrow's list treats them as a follow-up; add ": check same person" if the match is only likely). Only under Contacts / Groups, or nothing → a real first message; leave it.
   Client/prospect = a "(TOP …)" tag, or `./pa wa_notes known "<chat name>"` finds them, or the preview is clearly about insurance, a policy, premium, claim, plan, investment, a meeting with the adviser or a referral. Skip groups, companies/brands/banks/deliveries, family, partner, colleagues and friends chatting socially. When in doubt, skip.
4. For each chosen chat: open it, wait 2 s, read ONLY the messages visible on screen (don't scroll up, don't open photos or files, never click links, never click in the message box, never react):
   `const M=document.querySelector('#main').getBoundingClientRect(),mid=M.left+M.width/2,h=innerHeight;[...document.querySelectorAll('#main [role="row"]')].filter(r=>{const b=r.getBoundingClientRect();return b.bottom>0&&b.top<h}).map(r=>{const c=r.querySelector('[data-testid="msg-container"]');if(!c)return '-- '+r.innerText.trim();const b=c.getBoundingClientRect();return ((b.left+b.right)/2>mid?'ME: ':'THEM: ')+r.innerText.replace(/\s+/g,' ').slice(0,300)}).join('\n')`
   (right-hand bubbles = the adviser; if the output is cut off, add `.slice(-8)` before `.map`). Then `./pa wa_notes add "<chat name>" "<2–4 line summary>" --last them|me --chat-date <date of last message>`: what was discussed, what they asked, any date/time/premium/meeting agreed, what the adviser needs to do next. No NRIC, policy, bank, card or phone numbers; health at most one short plain line.
   **Decide from the conversation, not from who spoke last.** Pick ONE:
   - **REPLY**: something from them is still unanswered (a question, a slot offer, a request, news), even if the adviser sent the last bubble and missed it.
   - **BUMP**: the adviser's message or question is waiting on them and they've gone quiet.
   - **NONE**: the loop is closed. Add nothing.
   For REPLY / BUMP / check-in, write the message the adviser would send: their voice (Voice.md, Preferences.md), one short WhatsApp bubble, picking up exactly where the chat stopped with its details. Never "just following up on my intro". Offer times only within the next 1–2 weeks and only slots free on their Google Calendar (list_events) and outside config.json schedule.blocks; if you can't check, ask which day suits. Then:
   `./pa todo_list add "<chat name>" "Your turn: <few words>" --draft "<message>"` (REPLY), `"Bump: <where it stopped>"` (BUMP) or `"Check-in: quiet since <month>"` (gone quiet). This replaces that person's generic nudge / older Your-turn line, so they keep ONE line with ONE ready message on the morning list.
   **Already sent**: if the chat (or their wa_notes note) shows the adviser already sent a reminder that is still open on the list (💰 premium, 🎂 birthday, intro, a dated follow-up): `./pa todo_list done "<name>"` (full name if it matches 0 or several). Note "already sent, taken off".
   **Paid**: if the screen clearly shows a premium was paid ("paid", "transferred", "GIRO deducted", a payment screenshot; not "will pay"): `./pa todo_list paid "<chat name>"` and note "paid ✅ (reminder closed)" (or "said paid" if there was no open reminder).
   **Claims and servicing**: if the chat is about a claim or servicing request (claim status, payout not received, wants to claim, change of address/payment mode/nominee, reinstatement, policy loan, surrender…): `./pa cases list`. Case open → if they asked for an update, the REPLY draft is a short status update from what the case shows (never a promised date or amount); if the adviser said they'd chase, `./pa cases note <id> "<date>: client asked for update"`. No case yet → don't open one (the checklist must come from the insurer's form, with the adviser's OK); post `./pa telegram_post cases "📎 <First name>: <request in a few words, no medical condition>. Open a case?"`. Never name the medical condition; no policy numbers.
   **Calendar**: compare with their Google Calendar (list_events, first name, next 30 days), following the add-meeting-to-calendar skill. A confirmed date AND time with no event → add it (automatically only if config.json calendar.auto_add_confirmed is true; otherwise put "📅 confirmed <when>: add?" in the report). An event the PA added whose details the chat now settles or changes (place agreed, time moved, call ↔ in person ↔ Zoom) → update it and its buffers. Cancelled, or an event the adviser made → never edit; put it in the report.
   Then mark the chat **unread only if the decision is REPLY** (unread = "I need to reply"): right-click the row → "Mark as unread", Escape to close the chat, check the green dot stays. BUMP, NONE and check-in chats stay read.
5. Press Escape, scroll the list back to the top and leave the WhatsApp Web tab open.
6. Append to the report a section "## Chats read tonight" with one line per person: name + REPLY/BUMP/NONE/CHECK-IN + a few words (e.g. "REPLY: asks where to meet Thu", "paid ✅", "📎 C2 asked for update", "📅 place → Tampines Hub"), plus "Gone quiet (check-in drafted)", "Newly tracked clients", "No WhatsApp chat" and "First messages checked: <n>; already messaged: <names>". No message quotes, no sensitive details. Post: `./pa telegram_post admin "WhatsApp check: <N> your turn, <M> waiting, <K> chats read" --file Drafts/Follow-ups/whatsapp-scan-<date>.md`
7. `./pa hq_status done follow-up "WhatsApp check: <N> your turn, <K> chats read → Admin topic"`. If a calendar call failed: `./pa hq_status needs follow-up "Calendar update blocked: <what>"`.
